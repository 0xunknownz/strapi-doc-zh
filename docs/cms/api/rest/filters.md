**Original:** The REST API filters feature allows filtering query results using operators like `$eq`, `$contains`, and `$between`, with support for complex filtering using `$and`, `$or`, and `$not`, as well as deep filtering across related content.

**中文译文:** REST API 的 filters 功能可以使用 `$eq`、`$contains`、`$between` 等 operators 筛选查询结果；同时支持通过 `$and`、`$or`、`$not` 组合复杂条件，以及跨关联内容执行 deep filtering。

**Original:** The REST API offers the ability to filter results found with its "Get entries" method. If Internationalization is enabled, it's possible to filter by locale. If Draft & Publish is enabled, it's possible to filter based on a `published` (default) or `draft` status.

**中文译文:** REST API 的 “Get entries” 方法支持筛选查询结果。如果 content-type 启用了 Internationalization，可以按 locale 筛选；如果启用了 Draft & Publish，还可以按 `published`（默认）或 `draft` status 筛选。

**Original:** Strapi uses the `qs` library to parse nested objects and build complex queries. Use `qs` directly instead of assembling complex URLs manually.

**中文译文:** Strapi 利用 `qs` library 解析 nested objects，从而构建复杂 query。建议直接使用 `qs`，不要手工拼接复杂 URL。相关说明参见 `docs/snippets/qs-intro-full.md`。

**Original:** Queries can accept a `filters` parameter with the syntax:

`GET /api/:pluralApiId?filters[field][operator]=value`

**中文译文:** Query 可以接收 `filters` parameter，基本语法为：

`GET /api/:pluralApiId?filters[field][operator]=value`

**Original:** When several fields are passed in the `filters` object, they are implicitly combined with `$and`.

**中文译文:** 当 `filters` object 中同时传入多个 fields 时，Strapi 会隐式使用 `$and` 组合它们。例如：

`GET /api/restaurants?filters[stars][$gte]=3&filters[open][$eq]=true`

只返回已经营业且 stars 至少为 3 的 restaurants。

**Original:** `$and`, `$or` and `$not` operators can be nested inside one another.

**中文译文:** `$and`、`$or` 与 `$not` 可以相互嵌套，从而表达更复杂的逻辑条件。

**Original:** By default, filters can only be used from `find` endpoints generated by the Content-type Builder and the CLI.

**中文译文:** 默认情况下，filters 只能用于由 Content-Type Builder 与 CLI 生成的 `find` endpoints。

## Example: Find users having 'John' as a first name

**Original:** Use `$eq` to find an exact match.

```bash
curl 'http://localhost:1337/api/users?filters[username][$eq]=John' \
  -H 'Authorization: Bearer <token>'
```

```js
const qs = require('qs');
const query = qs.stringify({
  filters: {
    username: {
      $eq: 'John',
    },
  },
}, {
  encodeValuesOnly: true,
});

await request(`/api/users?${query}`);
```

**中文译文:** 使用 `$eq` 查找 username 精确等于 `John` 的用户。cURL 与 JavaScript 示例保持原样。

## Example: Find multiple restaurants with ids 3, 6, 8

**Original:** Use the `$in` filter operator with an array of values.

```bash
curl 'http://localhost:1337/api/restaurants?filters[id][$in][0]=3&filters[id][$in][1]=6&filters[id][$in][2]=8' \
  -H 'Authorization: Bearer <token>'
```

```js
const qs = require('qs');
const query = qs.stringify({
  filters: {
    id: {
      $in: [3, 6, 8],
    },
  },
}, {
  encodeValuesOnly: true,
});

await request(`/api/restaurants?${query}`);
```

**中文译文:** 使用 `$in` 并传入数组，可以一次匹配多个精确值。上例查询 id 为 3、6、8 的 restaurants。

## Complex filtering

**Original:** Combine `$and` and `$or` operators for complex filtering.

```bash
curl 'http://localhost:1337/api/books?filters[$and][0][$or][0][date][$eq]=2020-01-01&filters[$and][0][$or][1][date][$eq]=2020-01-02&filters[$and][1][author][name][$eq]=Kai%20doe' \
  -H 'Authorization: Bearer <token>'
```

**中文译文:** 该查询表示：book 的 date 必须等于 `2020-01-01` **或** `2020-01-02`，同时 author.name 必须等于 `Kai doe`。可以通过嵌套 `$and` 与 `$or` 组合复杂逻辑。

**Original:** The response only contains a book's own attributes. The `author` relation traversed by the filter is not returned unless requested through `populate`.

**中文译文:** Filter 可以沿 relation 进行匹配，但 response 默认仍只返回 book 自身 attributes。若希望同时返回 `author` relation，需要显式添加 `populate`，例如 `&populate=author`。

## Deep filtering

**Original:** Relations, media fields, components, and dynamic zones are not populated by default. Use `populate` to include them. You can filter populated and nested relations, but filters cannot be used for polymorphic structures such as media fields and dynamic zones.

**中文译文:** Relations、media fields、components 与 dynamic zones 默认不会被 populate。需要通过 `populate` parameter 显式返回这些结构。可以对 populated relation 和 nested relation 继续筛选，但不能对 media fields、dynamic zones 等 polymorphic content structures 使用 filters。

**Original:** Deep filtering may cause performance issues. If a deep-filtering query is too slow, build a custom route with an optimized query.

**中文译文:** Deep filtering 可能带来性能问题。如果某个 deep-filtering query 太慢，建议创建 custom route，并针对实际数据结构优化 query。

**Original:** Example: find restaurants owned by a chef who belongs to a 5-star restaurant:

`GET /api/restaurants?filters[chef][restaurants][stars][$eq]=5`

**中文译文:** 示例通过 relation 深度筛选：查找 chef 所关联 restaurants 中存在 5-star restaurant 的 restaurants。

```js
const qs = require('qs');
const query = qs.stringify({
  filters: {
    chef: {
      restaurants: {
        stars: {
          $eq: 5,
        },
      },
    },
  },
}, {
  encodeValuesOnly: true,
});

await request(`/api/restaurants?${query}`);
```

**Original:** Relations traversed by the filter are not returned by default. Add a `populate` parameter such as `&populate[chef][populate][restaurants]=true` to include them.

**中文译文:** 与普通 filter 一样，deep filter 遍历到的 relations 默认不会出现在 response 中。如果需要返回 `chef.restaurants`，可增加 `&populate[chef][populate][restaurants]=true`。
